# Codex Task Town — 共享像素工作室

一个只读、本地优先的 Codex Desktop 任务看板。每个任务会话是一位像素居民，普通程序采集事件，浏览器播放动画；看板不调用模型、不需要 API Key。

**当前版本：0.4.1。**第一阶段只做人员／任务工作状态。营地与村庄的「项目建设进度」是第二阶段，等工作室完成真实桌面联调后再开发。工作事件数量不等于项目完成度。

## 运行

需要 Node.js 22 或更高版本；macOS / Linux 安装脚本。不需要 `npm install`。

```bash
npm start
```

打开 `http://127.0.0.1:4317`。`/?demo=1` 是显式的模拟演示，不代表真实任务。没有事件时显示空工作室，不会用演示数据冒充实时状态。

网页有窗边长台、共享桌、白板、测试区、阅读角、咖啡角和沙发。任务目标、当前动作、文字状态和最近信号常驻显示，不依赖点击、悬停或动画。桌面与手机均有跨房间任务名单；点击人物或详情只补充历史和命名。支持任务搜索、状态筛选、分页；自检／历史记录不计入工作数。手机上可横向浏览场景。动画可暂停，并响应系统的减少动态效果设置。

## 共享任务名称：看清谁、在做什么

职业装扮不等于任务目标。未配置名称时明确显示“未命名任务”，不会通过模型猜测任务内容。每行显示的是 **任务目标 + 最近活动**，而不是把“正在修改代码”当成完整任务说明。编号用于当前名单和场景对应，过滤、翻页不会改变编号；任务集合变化时编号可能重排，稳定身份仍是完整任务 ID。

点击“工作中”统计可显示全部房间的工作名单。场景会说明当前可见数，名单支持点击定位其他房间；搜索同时匹配任务名、项目名、编号、活动和状态。断线、过期或关联不明时改成“上次：…”并移出工作计数。最近信号时间不是运行时长，活动数也不是项目完成度。

网页内的命名仅在当前浏览器生效。**多人查看同一个网站**时，管理员可在看板服务的数据目录（默认 `~/.codex-task-town/`，或 `TOWN_DATA_DIR`）创建 `labels.json`：

```json
{
  "version": 1,
  "tasks": {
    "0123456789abcdef0123": "修复登录权限",
    "abcdef0123456789abcd": "回归权限测试"
  },
  "projects": {
    "fedcba9876543210fedc": "示例项目后台"
  }
}
```

**以上 ID 只是格式示例**。真实 ID 可在居民档案复制（完整 20 字符任务 ID、项目 ID）。名称是允许向所有已授权查看者展示的纯文本，限 1–64 字符；不要包含秘密、客户信息或内部路径。更改配置后正常重启看板服务；不修改 Hooks、不读取对话或提示词、不新增模型调用、不增加远程写入接口。只发出当前任务对应的名称，不下发整份映射。缺少文件不影响原有接入，畸形文件会明确阻止启动，不覆盖旧事件或任务快照。本机昵称可覆盖共享名称，并标明“本机名称”。

示例文件在 `docs/labels.example.json`；本版计数与验证说明在 `docs/TASK_LIFECYCLE.md`。线上部署需要完整同步代码，并通过 `npm start` 启动新版适配器；仅刷新网页或只更新 HTML 不会完成升级。仓库当前 CI 不包含网站部署。

## 接入 Codex Desktop

先在终端进入本项目目录：

```bash
npm run hooks:preview
npm run hooks:install
```

在 Codex 桌面应用里审核、信任新增或变更的 Hooks，然后开始一个新的任务或回合。安装器保留其他 Hooks 并备份已有 `hooks.json`；监控脚本复制到内容指纹目录，脚本变动会改变配置中的路径，不能静默沿用旧的信任。

```bash
npm run probe           # 合成事件自检，不代表 Desktop 信任已通过
npm run hooks:uninstall # 仅移除本项目标记的 Hook 条目
```

默认文件位置：

- `~/.codex/hooks.json`：用户级 Hook 配置；遵循 `CODEX_HOME`。
- `~/.codex-task-town/integration/<fingerprint>/`：固定路径的采集脚本。
- `~/.codex-task-town/spool/`：仅包含规范化事件的本地队列。
- `~/.codex-task-town/state.json`：任务快照与重放去重标识。

更换 Node 安装路径后需重新运行安装器。使用 `TOWN_DATA_DIR` 时，安装和启动服务必须指向同一个目录。已有任务等下一次事件发生后才出现，不扫描历史对话。

## 数据与状态规则

```text
Codex Desktop → 本地 Hook → 规范化事件文件 → 单实例采集器 → SSE → 浏览器动画
```

`PreToolUse` 区分编码、读取、测试和普通命令；`PostToolUse` 只核对该工具是否返回，不代表整个任务结束。审批请求优先突出；其他并行工具的返回不会清掉它。`Stop` 只标记「观察到本轮收尾」，不标记「需求已完成」。收尾之后同回合的异步事件可能迟到，不能作为新工作的证明；等待新的回合／提示信号确认继续。长时间无信号、断线或保存异常时，显示状态待确认，而不是休息。

每个独立会话具有稳定身份。携带 `agent_id` 的事件和子任务生命周期使用独立身份，保留父任务关系；未带子任务标识的工具事件只能按来源会话归类，**不保证识别所有内部子代理操作**。规则识别不了的命令显示一般活动，不编造工作含义。

人物位置与短期工具动作分离。居民先分配到固定逻辑房间，再过滤；跨页搜索也不会把不同房间的居民挤到同一座位。等待和状态未知保持位置。只有明确 idle 的输入才进入休息区域。当前纯 Hooks 不能权威证明每一刻的 idle；因此真实任务可能长时间显示「收尾／状态待确认」，不能把演示中的休息状态当作已验证的桌面能力。

## 隐私与开销

默认不保存原始提示词、命令、代码、工具输出、绝对路径或原始会话标识。角色通过本地规则判断，任务身份使用哈希；**哈希不是匿名化或加密保证**。只保存短模板文案和有限历史。

```bash
npm run hooks:install -- --filenames
```

上述选项显式开启文件 basename 显示；常见敏感名称会被过滤，但过滤不是完整 DLP。网页昵称默认仅存在当前浏览器；管理员配置的 `labels.json` 则对所有查看者生效。请勿把秘密写进名称或文件名。

没有额外模型调用，不返回 `additionalContext`、审批决定或改写工具参数。高频 `PreToolUse`、`PermissionRequest`、`PostToolUse` 采用异步脚本，避免逐次等待记录完成；少量生命周期 Hook 保持同步以保留开始／收尾边界。内部约 800ms 看门狗，配置 1 秒超时，尽力退出 0；**不等于零延迟、零系统开销或任何故障都不可能影响宿主**。异步事件可能乱序、取消或缺失；不能据此承诺完整追踪。输入超过 1MiB、队列约满 2000 项或存储不可用时，丢弃监控数据而非工作数据。角色动画只消耗浏览器资源。

采集器每批先落盘快照与去重标识，再删除对应队列文件。写失败保留队列；第二个服务不能同时消费相同目录。历史和任务数有上限：200 位居民、每位 16 条历史，每页 8 位。关联表有界；标识缺失、相同并行命令歧义或超出容量时显示待确认，不默默猜测。工具失败也会过期。`npm run probe` 的居民明确标注「自检」，计数与非探针事件分开；旧版本来源不明的记录标注「历史记录」。这些标签不是来源认证，任何同系统用户仍能构造事件。这不是永久审计日志。

### 故障恢复

正常 `Ctrl+C` 会关闭服务并释放目录锁。强杀或异常退出可能留下 `collector.lock`；程序不再凭 PID 自动抢占遗留锁，因为检查与删除之间可能发生竞争。先确认指向该目录的所有采集器均已退出，保留快照和队列，再处理遗留锁、重新启动；不要在另一个服务仍运行时删除它。损坏、非普通文件或不支持的快照会阻止启动，并保留原文件供检查，不能直接覆盖成空工作室。恢复后旧的活跃状态显示待确认，直到收到新证据。

## 局域网只读分享

默认只绑定本机。不建议暴露公网。在可信网络使用足够随机的查看令牌：

```bash
export TOWN_VIEW_TOKEN="$(node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))')"
TOWN_HOST=0.0.0.0 npm start
```

其他人用你的局域网 IP 和端口打开网页，在「接入指南」输入令牌。身份凭证放在请求头，不放在 SSE URL 查询参数。HTTP 不加密流量；不可信网络应使用受控 HTTPS 反向代理或可信隧道。服务有严格 Host / Origin 限制，默认不支持随意配置的代理域名。网页 API 只读，不提供批准命令或调度任务接口。

常用变量：`PORT`（4317）、`TOWN_HOST`（127.0.0.1）、`TOWN_DATA_DIR`、`TOWN_VIEW_TOKEN`、`TOWN_STALE_MS`（120000）。

## v0.4.1：为什么“总任务数”以前一直增加

以前显示的是所有保留会话的数量，包含关闭会话、临时子任务和历史记录，并不等于当前正在负责工作的主任务。
现在统计采用独立的时间窗口视图，底层事件和任务身份不改动：

- **近期主任务**：默认近 30 分钟有事件且未收到 SessionEnd 的主会话。这个数不包含子任务、自检、旧版来源和历史记录，也不等于忙碌人数。
- **主任务工作中 / 需留意 / 收尾待命**：对同一批近期主任务分类。已有的 2 分钟信号过期规则保持不变；过期先显示未知，不能假装休息或完成。
- **子任务**：有明确 parentTaskId 的任务另计，默认名单直接显示它归属哪个主任务，不和父任务重复计人数。SubagentStop 只把观察到的子回合移入历史，不宣称整个需求完成。
- **历史**：会话已关闭，或超出近期窗口的记录。数据保留；超过窗口不是完成判定。恢复同一会话后复用原 ID，不生成第二个小人。
- **自检 / 旧版**：独立查看，不增加主任务人数。底部累计事件数可以持续增加，但明确标为事件数，而不是任务数。

子任务近期仍有非自检事件时，父任务保留在近期名单；这不会让父任务自身被判定为工作中。缺失父任务时不凭空生成一个主任务。
历史保留和当前计数不是一回事。最多保留 200 条任务记录，达到上限优先淘汰历史、自检和子任务，避免临时任务挤走近期主任务；这不是永久审计档案。

可设置 `TOWN_CURRENT_WINDOW_MS`（毫秒，默认 1800000，至少为 `TOWN_STALE_MS`，最大 30 天）。修改窗口只影响展示范围，不修改事实状态或丢弃记录。
HTTP `/api/snapshot` 返回 `currentWindowMs`、各任务 `scope` / `archiveReason` 和 `roster` 统计，可用于对照实际部署的计数。旧版 version=1 快照自动重新分类，无需删除 state.json。

从 main 升级时先正常停止服务，执行 `git pull --ff-only origin main`、`npm test`、`npm start`。v0.3.0 至本次没有改动 recorder/normalize/setup，无需因为此次升级重新安装 Hooks。
已部署站点的代理/数据转发配置不在本仓库；发布时保留部署定制，并同时更新前后端。仓库更新不代表服务器已重启或线上已发布。

审查和新测试见 `docs/TASK_LIFECYCLE.md`。此前报告保留各自版本的执行事实，不代表本次结果。

### 保留现有服务安全模块

本次未修改 `src/server.mjs` 的 HTTP 鉴权、Host/Origin 校验或落盘实现。`npm start` 使用小型启动适配器 `src/start.mjs` 加载共享名称与窗口参数；直接运行旧 `src/server.mjs` 仍能采集，但不会加载这些启动配置。发布脚本请使用 `npm start` 或 `node src/start.mjs`。
前端源码由 `npm run build` 合成为原来允许访问的 `app.js` 和 `styles.css`，已把产物提交，使用者不需要安装构建依赖。`npm test` 会检查源码与产物一致。`/api/snapshot.appVersion` 标识看板版本；保留的 `/api/health.version` 是原采集服务的版本，不能用它判断新版 UI 是否已部署。
