# v0.4.1：任务计数与默认可读性修复

## 审查基线与范围

基线 main `974be0e0dbfd84a889f5907ae479f9f9c887d152`；本地 v0.3 源码的 Git tree 与远端 `3dafcffda0ee4a53cbab593f21047c363d781eeb` 完全一致。
合入此前尚未落到主分支的 v0.4 工作名单/共享名称，并修复当前人数不断积累问题。仅共享工作室，不开发项目进度营地。

线上地址在本执行环境 DNS/网页抓取失败，没有读取服务器真实任务或修改线上数据。以下根因来自源码和复现测试，不推断线上每一条任务的来源。

## 根因

1. `TownStore` 保留已关闭会话，前端却把所有记录长度当成总任务数。保留历史是合理的；拿历史集合当当前人数是错误的。
2. 子代理具有独立身份，但此前与父任务同级计数。重复开启临时子代理会让“人数”不断增加。
3. 过期仅改变显示状态，不改变当前列表的范围；旧记录长期占用当前房间。
4. 到容量上限时单纯按最后时间淘汰，可能先删掉一个很早启动但仍有子任务工作的主会话。

## 修复

共享纯函数 `public/lifecycle.js` 为服务端和浏览器提供相同的范围与计数规则。默认当前窗口 30 分钟可配置；当前主任务计数不包括子任务、自检、历史或旧版来源记录。
SessionEnd 进入历史；子回合收尾进入历史并标注并非需求完成。超过窗口的观察移入历史，状态仍保留为最后事实；无新消息绝不推断完成。
同一 session 的多轮事件共用同一身份；继续旧任务不会多生成一条。归属明确的子任务单独显示父任务名，父任务未被观察则明确写出，而非制造主任务。
最近子任务证据使父任务仍可发现，但不覆盖父任务自身状态。容量淘汰也考虑这个家庭关系，优先保留近期主任务。
浏览器每秒重算范围，服务快照也按时间计算；不等待新 Hook 才更新计数。旧 version=1 快照无需清空，自动按新的展示规则分类。

默认名单按工作、需留意、收尾和子任务常驻显示；历史与自检有独立计数/视图。删除“必须点击定位”的引导和内部固定高度滚动限制。任务身份、动作、状态与信号时间直接可读；点击只作为可选操作。

旧测试中“已关闭会话占当前房间”和“探针算总任务”的断言已按正确产品语义调整，未删除对应验证。

## 接口与取舍

`roster.current`、`working`、`attention`、`quiet` 都以主任务为单位。`children`、`archived`、`reference` 单独统计；`retained` 才是最多 200 条记录的总数。默认列表可同时包含当前主任务与子任务，标题明确两者数量，不再叫累计记录数为“当前任务”。
近 30 分钟是观察窗口，不是权威在线/完成判定。长时间无事件的工具可能仍运行，界面只能保留上次证据。多机器、缺失 agent_id 的工具归属和未触发事件仍受数据源限制。
不同会话不按相同标题、角色、目录合并，避免合错真实并行任务。哈希不是身份认证，不读取/外发原始提示词。
当前公开 Hooks 文档说明 `session_id` 是当前会话，子任务 Hook 使用父会话 ID 并带 `agent_id`；`SessionEnd` 不用于子任务。核对来源：https://learn.chatgpt.com/docs/hooks （2026-09-15）。
