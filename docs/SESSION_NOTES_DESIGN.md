# 会话回复摘录：已做 / 正在 / 下一步

状态：设计方案，尚未启用聊天采集或上线。v0.4.1 包含此前的常驻任务名单与计数修复，不把它们说成已接入聊天内容。

## 用户目标

不点击、不定位、不打开聊天记录，也能看清每个 session 前面做过什么、当前在做什么、明确准备怎么继续。保留共享像素工作室；不开发第二阶段项目进度营地。

## 信息来源与展示

每个任务卡片常驻显示：任务目标、工具观测状态、最近工作说明、上一轮回复摘录、明确提到的下一步。每条说明保留时间与来源。

- 之前：助手对前一轮的用户可见回复摘录。标为“上一轮回复”，不是看板独立验证的完成证明。
- 当前：最近的用户可见进度说明，旁边保留 Hook 观察到的编码/测试/等待等状态。两者可能有时间差，不相互覆盖。
- 下一步：仅从原回复中明确表达的计划取句，例如“接下来会补充测试”。未提到时写“暂未说明”，不由模型补写，不把计划当执行证据。

示例文案仅用于设计：
任务：登录权限修复
之前（回复摘录）：已完成权限边界检查。
当前（最近说明）：正在调整登录校验；工具信号：编码中。
下一步（明确计划）：补充过期会话测试。

## 接入设计

优先使用 Stop / SubagentStop 的 last_assistant_message 字段获得收尾回复。
中途进度需要利用 transcript_path 的增量读取。记录格式不是稳定接口，必须提供按格式版本隔离的适配器、受控 fixture 测试、无法识别时停止提取的降级机制；不能声称仅凭 Stop 就能实时看到中途说明。
对子任务使用 agent_id 和 agent_transcript_path 的明确归属，不把父会话内容随意归给子任务。缺少可靠归属时不显示具体摘录。

Hooks 只发信号或记录必要定位信息，不同步扫描整份长对话；采集器按文件游标处理新内容，重复消息按 ID 或内容哈希去重。只保存助手用户可见文本（commentary/final）；不采集用户提示、系统/开发者指令、隐藏推理、工具原始输出或代码块。

“过去 / 当前 / 下一步”用保守规则抽取短原句，不增加大模型调用，不要求 Codex 专门生成看板日志，不把内容反馈回模型上下文。明确信息不足时保持空缺或显示未说明。

## 公开站点的数据边界

采集和发布分开授权。默认不能因为升级代码，就把本地对话公开到网站。应按项目/会话显式允许，支持仅本地保留、停止采集和清除摘录；升级安装的新 Hook 仍需正常审核信任。

建议每栏约 60–100 字，最长 160 字，保存最近 3–5 条原句摘录。任何裁剪标注省略，内容变化才更新。敏感模式过滤只能降低风险，不能保证去掉所有秘密；疑似凭证、个人资料、内部路径等不发布。服务器只接收允许公开的摘录，不接收原始聊天文件和本地路径。

摘录含自然语言时只能作为不可信文本，用 textContent 显示，不渲染不受控 HTML/链接，不执行其中的命令，不改变审批或任务调度。停止、过期和恢复都不因出现一条历史回复而变为活跃。

## 验收

1. 暂停动画、不点击时能读到任务与三类信息；缺信息时不编造。
2. 同一消息重放不重复；旧回合回复不覆盖新回合的当前说明；新回合明确清除旧计划或标为上轮计划。
3. 两个会话与子任务不串文；缺失字段、截断文件、格式变化和文件轮换安全降级。
4. 用户提示、隐藏推理、工具输出和敏感内容不进入公开摘录；HTML 只能作为文本显示。
5. 没有新的回复时不反复改写、不额外调用模型；长文件只增量读取。
6. 聊天摘录不能制造新任务、增加主任务总数、刷新真实工作状态或宣称代码已验证。
