# v0.3.0 第一性原理审查

日期：2026-09-14。基线：PR #1 / `397e723`，其 Git tree 与输入的 v0.2.0 源码包完全一致。范围仅为共享工作室，不开发营地或项目进度。

## 先确定产品必须守住什么

1. **展示的是观察证据，不是权威调度状态。**人物的动作不能比事件证据更确定。等待不是休息，收尾不是需求完成，连接在线也不等于 Hook 正常或任务仍在执行。未知是正确的业务状态，不是需要隐藏的错误。
2. **观测不应支配被观测工作。**不加模型调用，不让 Agent 上报动画，不输出审批决定；高频采集不能逐次同步等待。可丢有界遥测，但不能为完整记录牺牲工作执行。
3. **状态来自身份、关联和生命周期，不来自日志到达顺序。**不同任务、回合、调用必须隔离；重复、迟到、缺字段和并行是正常输入，不是异常边角。
4. **失败必须可恢复且不能伪装健康。**先持久化再确认消费；不丢弃损坏的原始恢复文件，不抢占可能属于其他进程的锁，不让一次失败永久卡死后续保存。
5. **测试证明一条具体结论，而不是用通过数量代替论证。**单元、真实本地链路、模拟 UI、真实浏览器、真实 Desktop 是五种不同证据。未执行／被拦截的测试不能计为通过。

## 测试不再只验证自己编出来的数据

保留手写的规范化 wire fixture，不让所有状态机测试都依赖同一个 normalizer 生成预期。增加真实安装脚本生成的命令，经 `/bin/sh` 运行 recorder，形成离线事件，再由真实服务读取并通过鉴权 HTTP 获取的整条测试。增加真实 SSE 故障恢复和真实子进程强杀验证。单工具所有六种到达排列都枚举，但这不等于穷尽任意多任务的全部排列。

模拟浏览器仍用于交互细节；另外新增 `test/e2e.py`，必须通过正常导航访问真实服务，验证 ES modules、CSP、认证、队列、已安装 recorder、任务状态和移动端。此次环境返回 `net::ERR_BLOCKED_BY_ADMINISTRATOR`，因此明确记录为 **受阻／未通过**，没有改成模拟或跳过来刷绿。CI 配置运行同一个严格测试，实际是否通过须查看对应 Actions 运行。

## 保留的取舍与未解决边界

- Hooks 不能证明权威 idle，不能完整看到未提供子任务标识的内部操作，也不能补回被取消或没有触发的事件。没有收到足够新证据时保持未知；营地进度仍不从活动次数推算。
- 异步 Hook 有并发上限、可能乱序，SessionEnd 仍同步；接入实际行为以用户安装版本为准。没有在用户 Mac 上启动 Codex 或操作其信任界面。官方合同来源：<https://learn.chatgpt.com/docs/hooks>（核对日期 2026-09-14）。
- 800ms 内部看门狗和有限队列是尽力监控，不是零开销保证；输入过大或记录超时可能丢遥测。没有做用户真实 Mac 的长期性能基准。
- 强杀后手动检查遗留锁是刻意取舍：牺牲无人值守自动恢复，避免未经可靠互斥证明就并发写入。测试只在隔离目录、已等待自有子进程退出后移除锁。
- 同系统用户仍可改队列、快照和昵称；非探针标记不是来源认证，哈希不是匿名化，HTTP LAN 不是安全公网服务。未增加自动信任、远程执行或审批 API。
- 事务顺序在进程故障和已测试写盘故障下验证；未承诺文件系统损坏、掉电、网络盘或敌对同用户竞争下无损。
- 位置对筛选稳定，但任务淘汰或总任务集合改变仍可能重新分房；昵称仍仅保存在当前浏览器，不代表已完成多人标签同步。

## 结论

共享工作室首先是一套有界、诚实、可恢复的状态观察系统，然后才是像素动画。v0.3.0 修正了输入相关、时间相关、存储恢复和测试证据边界；不宣布 phase 1 已完成真实 Desktop 验收。版本升级需重新预览、安装并信任更新后的 Hook 配置。
