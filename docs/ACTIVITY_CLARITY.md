# v0.4.0：从“有几个在工作”到“谁在做什么”

## 依据与范围

用户反馈部署后看见 4 个工作任务，但无法识别是哪 4 个、在做什么。本次环境无法访问 `https://town.tinghai.xin/`（网页抓取失败；容器 DNS 不可用），未验证线上真实任务或部署版本。审查基于 GitHub `main` 的 `974be0e`；输入源码与远端 tree `3dafcffda0ee4a53cbab593f21047c363d781eeb` 完全一致。没有更改线上配置、自动部署、读取对话或扩大权限。

## 已确认的设计问题与修复

1. 桌面隐藏文字名单，只能认动作和气泡。现在桌面、手机均常驻名单，优先列工作任务，明确列出目标、角色、动作、最近信号和房间。
2. 全局人数和单房间场景混在一起。现在统一 `overview.js` 派生计数、筛选、名单；名单跨房间完整显示，场景注明可见数，数字按钮可筛选并清除搜索。
3. 找到名字后仍不知道对应哪个小人。名单和人物共用编号、头像，条目点击切换到对应房间并高亮；详情是独立动作，不用弹窗遮住定位结果。
4. 职业加短 ID 被当成任务目标。现在明确“未命名”，支持管理员通过可选、只读 `labels.json` 配置共享任务和项目名称。文件不包含 prompts，不猜业务含义；本机昵称仍可覆盖但明确仅本机。
5. 颜色／动画不足以区分工作与收尾。人物增加常驻文字状态标签和工作强调；名单分组。自检与历史参考不计入工作数，过期／断线改为上次观察而非继续工作。

这仍是只读观察系统：收尾不是需求完成，最近事件不是实时存活证明，工作计数不是项目进度。营地／村庄继续延期。没有新增模型调用，没有改动 recorder、normalizer、状态机或 Hook 安装器。

## 测试证据

- 修改前本地 Node：85/85 通过。
- 修改后本地 Node：96/96 通过，0 失败／跳过；新增跨房间四任务、计数与名单相等、搜索、身份、过期、断线、自检排除、共享名称校验和真实鉴权 HTTP 测试。
- Chromium 模拟 UI：22 项检查通过。特别验证 4 个工作任务分布于 3 间房、第五个活跃探针不混入计数、四条工作记录同时可见、点击 17 号跨房间定位且不弹窗、项目搜索、键盘焦点、客户端过期；桌面 1440×1100、手机 390×844。
- 严格浏览器 E2E：已扩展为读取磁盘共享名称、通过真实 HTTP/SSE 显示名单和核对计数。当前环境正常 localhost 导航返回 `net::ERR_BLOCKED_BY_ADMINISTRATOR`，本地受阻，不计为通过。须以当前提交的 GitHub CI 结果为准。
- 未验证用户真实站点、反向代理部署、Mac 的 Codex Hooks 或实际任务名称。测试截图含演示／合成 fixture，不是线上真实任务。

## 部署与验收

从 v0.3.0 升级无需重装 Hook，只需同步整个版本、正常重启服务。静态资源新增 `/overview.js` 与 `/clarity.css`；后端新增 `src/labels.mjs`。自定义静态托管或代理应确认这些路径不是 404，不能只更新 HTML。

部署后用实际已知的任务核对：工作计数与名单一致；跨房间定位正确；任务名不是职业名；审批与自检不混入工作计数；信号过期后移入待确认；两个浏览器显示一致的共享名称。管理员提供的共享名称必须适合目标网站的访问范围。
