# v0.2.0 设计与代码审查

审查对象：此前提供的 v0.1.0 源码包；仓库此前只有初始 README 和功能分支。

| 优先级 | 发现 | 已落实的修复 |
|---|---|---|
| 高 | `e.at < lastAt` 丢弃同回合中迟到的并行工具结束事件，留下错误的 pending | 生命周期边界与工具核对分离，按工具关联 ID 清理；lastAt 取最大值，旧回合不能复活 |
| 高 | 消费事件时先删队列、每秒再保存状态，进程崩溃会丢事件 | 每批先写入并同步快照，再原子替换、确认删除；失败保留队列；持久化去重标识 |
| 高 | 多个采集器可以消费同一目录 | 增加单实例目录锁；活跃或无法判断的锁拒绝启动，死进程锁可恢复 |
| 高 | 无工具 ID 的结果清空所有 pending，其他并行结果清掉审批提示 | 优先按 callId；审批缺少 ID 时只用工具输入指纹匹配；保留其他审批 |
| 中 | 子任务共享父会话标识，无法仅按 session_id 区分 | 存在 agent_id 时独立标识，记录 SubagentStart / SubagentStop 和父任务关系；无标识路径明确标注限制 |
| 中 | SessionStart 直接等于 idle，收尾状态永久保鲜 | 会话打开先显示未知；收尾信号也适用过期规则 |
| 中 | SSE 查看令牌出现在 URL 查询参数 | 改为 fetch 流式读取，令牌仅在 Authorization 头；服务拒绝查询参数认证 |
| 中 | 无效队列数据未计入 rejected，恢复时 null 历史可抛异常 | 规范校验、错误计数、恢复字段白名单；拒绝队列符号链接 |
| 中 | 队列事件写失败时 probe 仍可能打印「成功」 | probe 检查规范化队列或已持久化快照，不只检查子进程退出码 |
| 体验 | 一人一张相同桌子、档案永久占位、手机字太小 | 共享家具与多区域、点击打开档案；手机可横向浏览场景并有可读任务列表 |
| 体验 | 过滤后位置变动，暂停时仍持续请求动画帧 | 保存居民位置；普通工具切换不换位置；页面隐藏或暂停停止动画定时器 |

## 已保留的好设计

本地优先、零运行依赖、无模型 API、Hook 输入先脱敏再落盘、静默退出、不输出审批决定或 additionalContext、保护现有 Hook 配置、脚本内容指纹触发重新信任、演示与真实事件隔离、固定上限的任务与历史。

## 仍需注意

1. 纯 Hook 事件是观察信号，不是权威任务调度状态。事件触发／本地脚本调度时间并非完全有序；ID 关联能处理已测试的乱序场景，但不能补回没有发送的事件。
2. 没有 agent_id 的内部工具事件无法保证逐个归属子任务；托管工具可能不产生本地 Hook。不会猜测缺失的轨迹。
3. 真实 idle 不由无日志推断；活动次数绝不被当作项目进度。第一阶段仍须在用户实际桌面环境验证。
4. 同步记录有启动与写盘开销，超时／输入上限会丢监控数据；不宣称绝对零延迟。快照不是永久审计日志，也不承诺硬盘损坏或突然断电情况下的数据恢复。
5. 同一系统用户仍能修改本地数据；不能把哈希当成匿名化，不把明文 HTTP LAN 服务当成安全公网服务。
6. 后端 API 不同步浏览器昵称；多人共享可读任务标签仍需后续本地配置方案，不能偷存原始提示词解决。
